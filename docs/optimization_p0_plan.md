# P0 评测后优化设计

**状态：设计待实施。** 本文依据 2026-09-19 的 [P0 离线基线评测报告](evaluation_p0_report.md)，将已定位的问题转为工程任务、实验方案和验收门禁。本文不包含新一轮实测结果。

**目标：** 修复原文候选过早丢失，改善有限 Top-8 的证据利用，补齐语料质量与评测记录，为独立评审提供可信输入。

**基线：** `20260919T092741Z-p0-1cc225b`；代码 `1cc225b3e606e516df289daff96883e92b49a57f`。后续实验记录自身代码、工作区差异和数据哈希，不能只沿用这个提交号。

**文档关系：** 本文的“P0 优化”指基线评测后的优先修复批次，不改变 [评测方案](evaluation_plan.md) 中 P0～P4 的阶段定义。长期方向沿用 [下一阶段开发文档](next_phase_development_plan.md)；指标定义与正式验收以较新的评测方案为准，不沿用旧方案中的绝对 Recall 门槛或未验证的历史分数。

## 1. 结论与范围

推荐先改善现有 `legacy + deterministic + extractive` 链路，再使用独立开发集评估新后端。P0 的主要问题已有明确的候选处理与数据线索，直接换模型会同时改变多个变量，无法判断收益来自哪里。

| 路线 | 收益 | 代价与限制 | 本次选择 |
|---|---|---|---|
| 修复候选策略，补齐记录与语料 | 直接对应已观测故障，可分步回归和回滚 | 不保证解决全部语义检索问题 | 推荐 |
| 直接启用 dense / cross-encoder | 可能改善语义相关性和 q008 排序 | 缺模型实测、独立 qrels；已有结果只验证缺模型回退 | 留在后续开发集实验 |
| 只补充文献、扩大 Top-K | 可增加可检索内容 | 不能修复原文被裁掉，增加预算也会破坏同条件比较 | 不作为单独方案 |

本批次交付包括：可追踪的候选流、原文保留策略、Top-8 选择实验、新版语料、可信的运行状态与回归报告。代码兼容 Python 3.9+，MCP 集成检查单独使用 Python 3.11 环境；不为这些修复新增必需模型依赖。

范围之外：重写 UI、完整知识页生命周期、默认切换模型后端、扩大临床适用范围、完成正式临床验证。本文只交付设计；实施期间也不得为提高应答率降低最少独立来源数或放宽安全阈值。

## 3. 设计一：原文保留与 Top-8 选择

### 3.1 已确认机制

[candidate_pool.py](../src/evidence_assistant/candidate_pool.py) 当前先按文本前 600 字符全局去重，再按研究家族分组，将知识页排在其他来源前，每家族只保留两条。报告中的五次原文丢失与最后一条规则一致。前缀文本去重还存在误合并风险，但本次报告没有证明它导致了这五次故障。

[pipeline.py](../src/evidence_assistant/pipeline.py) 对全池重排后直接截取 Top-8；[rerank.py](../src/evidence_assistant/rerank.py) 的互补选择只作用于生成 Top-5，不能补回候选池或 Top-8 已经丢失的文档。

q008 的低排名是已知结果，具体分数成因尚未完成消融。知识页先验、词项相关性和重复占位都是待验证因素，不能直接认定某个权重是根因。

### 3.2 三种身份分开使用

| 身份 | 用途 | 约束 |
|---|---|---|
| `entry_id` | 一个具体 chunk/claim 的追踪与引用映射 | 保留完整文本哈希、输入支路和保留/删除原因 |
| 文档/页面身份 | 同一文档或知识页的占位限制 | 发表文献优先用已核实 PMID/DOI；NCT 仅作为注册记录自身身份，不合并同研究的不同发表；知识页按自身 `doc_id`，使用独立命名空间 |
| 研究家族身份 | 防止同一研究被当成多个独立来源 | 同研究多发表、知识页与所引原文不因表示数增加而增加独立研究计数 |

知识页的被引来源只表示溯源关系。不能用 `canonical_source_id` 直接合并页面和原文，也不能把命中页面改算成命中页面引用的所有 PMID。旧 qrels 对页面和原文的标注保持原样。

当前 `research_family_id` 主要依据 NCT，缺失时回落到规范来源；知识页的多引用可能受首个标识影响。P0 不把它升级为完整研究家族图谱：记录多引用、别名冲突和不确定映射，不把引用列表展开为多个“已检索到的独立来源”。缺少可靠身份的条目不参与抬高独立来源计数。

### 3.3 候选池策略

1. 对同一 `entry_id` 的重复表示先选择最高检索分数的有效条目；平分依文档身份、完整文本哈希和来源名确定，不能依赖支路输入先后。身份冲突不得仅按分数覆盖，须记录并隔离该冲突。
2. 文本去重键改为“表示类别 + 文档/页面身份 + 完整规范化文本哈希”。只合并同一文档的重复表示；同文不同文档保留各自出处。为被合并条目记录 survivor ID 与来源别名。
3. 保留同文档的不同段落和同页面的不同 claim 进入重排；取消 build 中每家族两条的提前截断。这样同 NCT 的多篇发表也有机会被相关性排序。
4. 本批次沿用既有召回预算，并记录实际池大小。legacy 的知识页/快照/PDF 分支现有配额为 12/14/18，不能把 `retrieve_k=40` 当成已导出的统一 Top-40。
5. [pipeline.py](../src/evidence_assistant/pipeline.py) 在实时 API 决策前也调用 preliminary build，最终合池再次调用 build；两处使用同一候选策略。启用新 Top-8 选择后，preliminary 仍使用 deterministic 对全池评分，再调用同一选择函数。用 mock 检查阈值两侧、latest、rag 和关闭 live 的调用行为，实际联网能力仍受原开关控制。

**保留的含义：** R1 的五个原文对必须存在于 pool-after；它们是否进入 Top-8 由排序决定。上游检索器仍有各自的返回配额，保护仅针对实际进入 build 的候选，不保证从全库召回全部相关原文。不能把“候选恢复”写成“召回达到 100%”。策略中禁止出现题号或指定 PMID 的特判。

候选集合变化会影响 BM25/TF-IDF 的 IDF 和归一化，即使权重不变也可能改变最高分及本地置信度。因此实时调用率和候选规模必须观测，不能先验承诺行为完全不变。

### 3.4 Top-8 候选选择策略

原排序器先对完整候选池评分，保留 `rank_before_selection` 与分数。随后测试以下确定性选择策略，作为独立于 R1 的实验变量：

- 依分数降序遍历，稳定平分键使用文档身份和 `entry_id`。
- 同一原文文档最多一个条目，同一知识页最多一个 claim；两者按不同命名空间计数。
- 同一已识别研究家族最多两个条目，允许页面和原文同时保留，也允许同研究不同发表各占一位；这些条目仍只构成一个独立研究来源。
- 满八条即停止；若候选身份过于集中而不足八条，则返回实际数量，不用重复片段补足，也不降低最少独立来源要求。
- 只有选择完成后才赋引用编号。生成 Top-5 只能引用最终 Top-8 的编号，互补选择不能重新编号或从池外补证据。

选择函数位于各重排后端的共同下游，deterministic、cross-encoder 及其回退均适用；策略异常须单列为选择失败，不能冒充模型降级或静默跳过约束。

这会改变可引用条目的组成，可能丢掉同一页面的另一个关键 claim。因此必须同时观察要点覆盖、必要角色、有效应答数和误拒答；不能只看唯一文档数量。如果覆盖退化，则保持 R1 修复、回退此选择策略，待独立开发集支持后再调整条目配额。

生成 Top-5 后再检查其实际独立来源数及预期证据类型；不得借 Top-8 中未传给生成器的材料满足生成前门控。仍使用当前 `minimum_independent_sources=3` 和既有类型规则；不满足则给出可解释拒答并记录阶段。这项安全复核先单独实现与评测，独立于 Top-8 实验开关；一旦作为安全修复启用，不随选择策略回滚。历史策略仅可在隔离的离线比较臂中复现。

### 3.5 q008 的诊断顺序

导出 PMID 29507099 与相邻候选的词法、TF-IDF、召回分数、知识页先验、证据类型先验，以及选择前后排名。先比较“仅修候选池”，再比较“增加 Top-8 约束”。若仍未入选，将其作为排序残余问题进入 16 题开发集分析；扩词、权重调整和模型重排另开实验，不依据单道旧题调出特例。

## 4. 设计二：语料治理与版本隔离

### 4.1 治理顺序

1. 冻结原 C1；创建候选语料 `C1-vNext` 和独立输出路径，保留清单、文件与索引校验和，不覆盖现有基线。
2. 核对 Other 来源：元数据缺失、未命中 `publication_type_to_level` 映射、分类冲突、确实属于其他研究类型，分别计数。元数据优先读取冻结缓存；新增网络采集另记采集日期和原始响应。
3. 优先处理高血压、脑卒中和检索高频来源，再完成全库分类审计。初始至少补足高血压 12 篇、脑卒中 15 篇的可用文献缺口；若重查后有失效或误分类，按真实缺口追加。
4. 对 19 个历史 magic 无效项逐项复查；对其余摘要兜底项解释具体原因。文件存在或 magic 正确都不足以证明内容与文献身份匹配，还需检查解析结果及来源一致性。
5. 重新建索引、审计完整性与文档—chunk 关系，生成机器报告后再冻结新版本。

### 4.2 语料门禁

| 门禁 | 目标与计算方式 |
|---|---|
| 可用文献量 | ≥500；至少有可检索、可引用的实质全文或摘要。只有标题的兜底不算达标文献 |
| 主题覆盖 | 高血压、血脂、糖尿病、脑卒中、心脑血管各 ≥20；沿用主主题计数，多标签覆盖另报 |
| Other 比例 | `Other / 可用文献数 < 50%`；分子分母来自同一候选语料，不靠剔除未知记录美化 |
| 全文率 | `有效全文文献 / 可用文献数 ≥90%`；摘要兜底如实标识，不伪装为全文 |
| 身份与完整性 | 主标识唯一，manifest 与索引一致，SQLite integrity_check 通过，孤立 chunk 为 0 |
| 异常闭环 | 每个失效文件记录修复、替换、摘要兜底或排除结果与理由；原始记录保留 |
| 知识页 | 结构 lint 无错误；引用内容是否支持陈述另行人审，lint 不能替代医学核验 |

若文献数仍为 500，Other 至多 249 篇才通过，即至少 150 篇需要有依据地重新分类或由合格文献替换；这只是算术下限，不是要求强行改标签。扩容后按新分母重算。无法证实类型的文献继续标为 Other，门禁未通过时如实报告。

[index_pdf_collection.py](../scripts/index_pdf_collection.py) 当前允许 `abstract or title` 形成兜底 chunk；[audit_corpus.py](../scripts/audit_corpus.py) 主要依据索引状态统计。因此需补充 title-only 与真实摘要的区别，保留“全部记录”和“可用文献”两套分布，避免借排除记录隐蔽改变统计口径。

### 4.3 最小语料台账

每条记录至少包含：规范来源 ID、主题、证据类型、类型依据和复核状态、来源 URL、获取时间、授权/使用范围或未知状态、文件 checksum、metadata checksum、解析版本、全文/摘要/标题状态、异常原因与处置、索引版本。未知授权不得推断为可再分发；本地文献和全文工件继续留在 Git 忽略目录。

不自动把所有 Other 当成“边界证据”。当前角色规则属于工程代理；必要角色覆盖最终应由题目要求和人工标注决定。语料分类调整会影响排序先验、角色和拒答，因此必须作为数据变化独立复测。

## 5. 设计三：可审计评测与安全记录

### 5.1 复用 P0 工件，固化可维护 runner

历史运行的 [复现说明](../data/eval_runs/20260919T092741Z-p0-1cc225b/REPRODUCE.md) 和 runtime 脚本留作审计资料。将可复用逻辑整理到版本控制下的 `eval/run_p0.py`、`eval/offline_runner.py`、`eval/run_record.py`，历史脚本和输出保持不变。

runner 必须拒绝覆盖已有 `run_id`；在干净子进程中显式构造全部 Settings，禁读项目 `.env`，清空凭据并关闭实时、云端和 LLM，设置本地模型模式与独立缓存。C0 的 PDF 路径必须明确不存在，C1 指向指定快照。配置白名单不能包含密钥或完整环境变量。

保留网络审计钩子及拒绝自检，报告其实际覆盖范围；这不是 OS 抓包证明。合成安全输入另用逐适配器 spy 验证前置阻断后调用数为零。

### 5.2 每题结构化工件

采用本地、显式启用的评测 recorder；默认产品响应只保留现有安全摘要。净化前原始输出不加入公开 Tool API 或 MCP payload，避免 `PipelineResult.to_dict()` 直接将其序列化外发。

| 工件/字段组 | 必须记录的内容 |
|---|---|
| `manifest.json` | baseline_run_id、代码与差异哈希、依赖、Settings 白名单、语料/qrels/评分器版本、种子、硬件及不可获取项 |
| `candidates.jsonl` | question_id、stage、entry_id、文档/家族身份、表示类型、支路、分数、排名、保留/删除原因、survivor_id |
| `answers.jsonl` | 原始生成、逐陈述稳定 ID、校验结果、删除原因、最终陈述、最终拒答理由；保留净化前后映射 |
| `timings.jsonl` | 初始化、首次请求、改写/安全、各召回支路、合池、重排、Top-8 选择、证据门控、生成、校验、净化、全链路、排队；未执行阶段记 `not_run` 且耗时为 null，不冒充 0 ms |
| `results.jsonl` | requested/actual backend、降级原因、运行状态、应答行为、实际 K 和来源数 |
| `summary.json` / `report.md` | 由同一结果计算指标、分子/分母、区间、门禁与未评估项；Markdown 不另行手填分数 |

阶段至少区分 `retrieved`、`pool_before`、`pool_after`、`reranked`、`top8`、`generation_top5`。preliminary 和 final 两次 build 分开标记，文档转 chunk 的展开与去重分别计数；每次删除或合并必须能追到原因，不能用不一致的计数单位强行对账。

默认 recorder 不持久化真实用户问题；仅在受控的去标识化评测集开启原始文本保存。前置 PHI 阻断项只记录合成用例 ID 和阻断码，禁止把输入写入错误栈或请求日志。

### 5.3 状态、评分与 A/B/C 边界

- `run_status` 使用 `success / error / skipped`；成功后另记 `answer_status=answered/refused`。降级是独立维度，必须同时有实际后端和原因。
- A 臂无 LLM 配置时标记 skipped，计数保留、质量指标记 N/A；不能计为错误或正确拒答。
- [baseline.py](../eval/baseline.py) 当前纯 LLM 基线直接发送题干，只有系统安全提示；[run_compare.py](../eval/run_compare.py) 的相同安全提示不能证明相同出站政策。后续比较入口需先共用输入预检，合成 PHI 在任一臂均不得到达外部适配器。
- C 臂保持标注为 `legacy_degraded_smoke`。之后实现的删除关键证据、注入矛盾、加入干扰证据须有各自固定策略与变化清单，不能把现有全拒答结果当成三类扰动结论。
- 旧 15 题、旧 qrels、旧评分函数冻结。新评分器另建 `eval/metrics_v2.py`，使用 0～3 分级、唯一文档与明确 Top-K 预算；重复位置计 0，不去重后补满 K。
- legacy 未提供有意义的统一 Top-40 时，该指标标记 N/A；不得按拼接顺序截 40 条充当检索排名。统一召回序列的实现应作为单独算法变量评测。

新评分器按等级 ≥2 判定 Recall/MRR 命中，MRR 截断到 8，nDCG 使用 `2^rel−1` 和完整 qrels 的 IDCG。没有正相关 qrel 时记 N/A；有证据但未检出记 0；未标注候选记 `unjudged`，不得自动按无关处理并据此排名。正式区间采用配对题组 bootstrap，相关改写和共享研究题按预定题组重采样；重复生成嵌套在题组内，不增加独立题组数。旧题没有可靠题组标签时继续只报探索性区间。

### 5.4 最小挑战集

本批次增加合成、可解释的工程故障用例：PHI 与个体化诊疗预检、虚构来源/越界编号、否定反转、数字或单位不匹配、空候选、错误解析、模型/索引缺失、外部源超时。涉及语义正确性的标签须经过独立复核；工程断言通过仅证明该测试场景，不构成完整临床安全结论。

检查范围包含正文以及 `limitations/found/missing/next_steps/reason` 和可见证据卡片。校验器的陈述—证据挑战集与用户问题集分开统计；原始输出、删除正确率、最终残留错误不能混成一个规则通过率。

### 6.2 本批次工程门禁

下列“建议目标”是本设计新增的内部工程判据，不是已测成绩，也不是正式盲测门槛。

| 门禁 | 通过条件 | 失败处置 |

| 原文候选保留 | 每个配置 5/5 已知原文对在 pool-after；身份/前缀误合并合成用例全部通过 | R1 不验收 |
| 排序基本回归 | C0/C1 旧 Recall@8 均不低于 75%；旧 nDCG 分别不低于 77.6%/75.5%（实际用未舍入值比较） | 检查逐题差异；不能只靠汇总掩盖关键丢失 |

| 回答与覆盖回归 | 每配置 12/12 旧应答题非空，3/3 旧拒答题仍拒答；词项覆盖不低于 B0 未舍入值（展示值 81.7%/80.0%），安全规则用例全部通过 | 先用 G1 区分安全复核与选择变化；选择造成退化则回退选择，安全复核暴露问题则独立裁定，不得放宽阈值 |
| 引用与身份 | Top-5 是 Top-8 的子集、编号映射无越界；同研究的重复表示不增加独立来源数 | 阻断合入受影响策略 |
| 数据质量 | 第 4 节全部门禁通过，异常处置与分类依据齐全 | C1-vNext 不宣称语料验收通过；代码修复可单独交付 |
| 状态与追踪 | 无记录丢失；success/error/skipped 分母对账；每个删除/合并可解释；实际后端完整 | 先修评测，质量结论暂记不可判定 |
| 可复现性 | 每配置两次确定性结果一致；原工件 checksum 未变 | 定位非确定来源，不追加样本掩盖差异 |

收益目标选择 21/24 是为了要求至少恢复部分损失，不能推导出独立题集上也能达到 87.5%。q008 必须单列排名变化；即使汇总达标，它仍可能未解决。

如修复暴露旧题标签本身不合理，冻结旧回归结果并提交独立复核，不为恢复 15/15 临时修改旧标签或降低门控。新版金标准另起版本；此时相应回归差异记为待裁定，不能静默豁免。

### 6.3 性能与入口验证

在同机同电源/线程、相同语料和缓存协议下，重测 B1 与候选：初始化、首次请求分列；预热 10 次，每配置每个并发等级至少 100 次应答请求；并发 1 和 4 分别报告 P50/P95/P99、排队、超时、错误与峰值内存。拒答快路径单列。

建议将“同条件并发 1 的离线全链路 P95 相对重测基线增加 >20%”作为需解释和复核的性能警报，不把历史 C1 的 62.43 ms 直接作为跨机器绝对门槛。新增的纯检索+重排时间单独报告；正式预算沿用 CPU ≤2.5 s / GPU ≤0.8 s，未测 GPU 记未评估。

核心环境可按预定范围跳过 MCP，但必须标为 N/A；Python 3.11 的 MCP 必测环境不能以缺依赖跳过代替通过。现有 [test_mcp_server.py](../tests/test_mcp_server.py) 使用进程内客户端，还需新增真实 stdio 子进程检查，验证 stdout 协议完整、stderr 日志分离、工具可发现及结构化应答/拒答。桌面 `--check` 沿用；浏览器和多平台安装仍需发布阶段单独验证。

### 6.4 与正式验收的衔接

48 题试点按 16 开发 / 32 盲测建立，由两名循证评审独立标注、一名仲裁者处理分歧；盲测由评测负责人保存，开发者不得查看盲测 qrels 调参。同意图改写和高度相关的研究题按题组划分，不跨开发/盲测泄漏。正式阶段扩至 200 题（60 开发 / 140 盲测），被查看过的试点盲测转为回归，不计入独立盲测。

正式指标使用新定义：可达召回完成率@8 ≥85%、分级 nDCG@8 ≥82%、最终陈述支持率和引用支持精确率各 ≥95%、数字正确率 ≥98%、加权要点覆盖率 ≥85%、两类安全有用回答率各 ≥80%、正确拒答召回率 ≥95%、误拒答率 ≤10%。这些均需真实分母、独立评审和区间；最差主题门禁还需每主题至少 12 道适用独立盲测题。

正式默认后端切换仍须遵守评测方案：严重错误阻断项通过，质量达标，RAG 安全、有用且可追溯回答率差值的 95% 区间下界不低于 −5 个百分点，并有明确质量或资源收益。未取得证据时保留现有后端，不能用本批次旧题回归替代版本决策。
