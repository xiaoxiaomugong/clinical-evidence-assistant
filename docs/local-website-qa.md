指定回归先复现为 `INSUFFICIENT_SOURCES`：混合检索测试的 fake index 取了知识页开头三条糖尿病候选，平分打分的 fake cross encoder 未把相关高血压证据排进足够的 Top-8 位置。问题覆盖筛选正确排除了跨主题候选，余下仅两组独立来源。修复仅调整测试夹具，使用真实高血压知识页和 WHO/TIME 快照的正文、引用及不同来源身份，并让交叉重排偏好一条可识别的高血压候选；索引明确禁用本机私有 PDF。用例现在要求稠密候选实际进入结果、交叉重排改变首位、门控达到三组独立来源且生成正常答案；没有降低门槛或跳过测试。未知通路、跨主题陈述和来源不足的既有拒答回归继续通过。

本轮再次启动本地 API 与 Vite，并用内置浏览器检查真实 HTTP 流程：公众版服药时间问题只展示 TIME 相关的两条摘录，引用详情显示 PMID 36240838；地中海饮食问题展示 PREDIMED/CORDIOPREV 相关陈述，没有混入限钠或降糖治疗；未知 `ZXQZ` 通路问题拒答且不残留上一题答案。专业版填写成人高血压、晚间服药、早晨服药、心血管结局后，返回一条 TIME 相关陈述及 PMID 36240838 的引用。切换入口时原公众版拒答仍保留其标签，直到再次提交。这次没有重跑首次验收的全部屏宽、键盘、故障注入和并发浏览器矩阵；其旧结果见下文。

首次验收发现的两类跨主题陈述，在本轮所测服药时间及饮食问题上已由问题覆盖筛选和生成后陈述过滤排除。当前语料规模仍仅五个知识页、十条快照，相关性规则尚未经独立题集与临床专家评审；三来源门控可计入同领域背景资料，最终回答可能只显示一个研究家族的直接引用。引用、数字和来源身份的工程校验不能证明医学正确率、证据确定性或资料时效。公网部署、跨浏览器矩阵、依赖在线安全审计和独立临床评审仍未完成。

首次推送的提交 `5784e7e` 对应 [CI 运行](https://github.com/xiaoxiaomugong/clinical-evidence-assistant/actions/runs/36742771844) 失败：网站任务只安装 Web/开发依赖，完整回归缺少 `pymupdf`；核心矩阵未安装 FastAPI，相关性测试却借用 Web 配置；runner 的 `XDG_CONFIG_HOME` 使桌面默认路径测试前提不成立；检索测试的 Top-8 又受到本机私有 PDF 索引有无的影响。已据日志改为网站 CI 安装 PDF 测试依赖、相关性测试独立构造离线核心流水线、桌面测试清除 XDG 覆盖、检索夹具禁用私有 PDF 并提供三个不同文档身份的真实高血压来源。本地已复现环境差异并重跑相关测试。最终提交的远端 CI 须按新 SHA 及其全部任务验收；本段写于再次推送前，不预先声称通过。本地浏览器复验已完成，临床评审未完成。

### 布局与数据边界

- 首页、公众回答、展开 PICO 的专业版、主题详情分别在 320、390、768、1280 CSS px 检查，文档宽度均不超过视口。
- 另目视检查 390 px 单栏表单/拒答和 1280 px 首页/专业双栏布局。
- 页面脚本与样式均由本机提供；没有远程字体、统计脚本、浏览器持久存储或原题 URL。
- 合成凭据、异常消息、内部路径及 trace 的防泄露测试通过；校验错误不返回原始输入。
- 开发代理故障日志已改为固定文案。用包含合成 URL/供应商标记的错误消息验证，日志不保留标记或连接堆栈。
- 故障注入产生一次预期 HTTP 500 浏览器网络错误；正常操作时未发现 JavaScript 运行异常。

### 验收中修复

1. 统一前后端 PICO 总长度计算，将标签、冒号和换行计入 4000 字符。
2. 公开来源补充已有研究类型、证据类型和发表状态，缺失时如实显示。
3. 修复 StrictMode 下引用弹窗立即关闭：模拟异步原生 `close` 事件的测试先失败，改用 `cancel` 处理用户 Escape 后通过；真实浏览器复验通过。
4. 过滤 Vite 代理错误中的原始连接堆栈与请求 URL。
